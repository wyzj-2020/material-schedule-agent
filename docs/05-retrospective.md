# 05 复盘

## 最难的问题

1. **在"预设骨架"与"模型动态决策"之间找到边界**。
   题目要求至少一个「选动作 → 执行 → 观察 → 调整」循环，但又允许预设流程作骨架，且明说固定分支不算数。难点在于：骨架如何约束流程、又不剥夺决策权。
   解法：骨架只作为"建议步骤"（先读、再查规则、再查时段、最后存草稿），每个节点之间的**具体动作选择**（补查/替代/确认/阻断、是否跳过查时段）交给决策引擎依据工具返回结果做出；用「硬性要求冲突时只能确认/阻断」作为不可逾越的边界，而非把整条路径写死。

2. **硬性要求的"确认边界"如何被强制执行**。
   仅靠模型自觉不够，于是把校验前移到 `save_draft` 的写边界：硬性发布时段（日期或时刻任一）被改的保存请求直接拒绝、不落盘；`guardrails.py` 再对最终结果兜底，若硬性时段被改且状态仍是 approved，强制改为 blocked。两道防线保证即便决策引擎出错，边界也不会被突破。

## 学习收获

- ReAct 循环的关键不是循环本身，而是**观察结果如何改变下一步**；Trace 里的 `decision_basis` 让"依据什么结果、为什么这么选"变得可评审。
- 去重应放在写操作的工具层（`save_draft`），而不是 Agent 层——这样无论模型如何调用，重复提交都只会产生一份草稿。
- 数据驱动的规则 DSL 让审核规则与代码解耦，评审只需改 `data/rules.json`。
