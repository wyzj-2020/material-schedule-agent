# 04 AI 辅助记录

## 使用范围

本项目由 **Claude Code（AI 辅助工具）** 协助完成，覆盖：

- 整体设计（架构、ReAct 循环、工具/守卫/去重机制）
- 全部代码实现（`src/`、`tests/`）
- 合成数据与示例输入（`data/`、`examples/` 的 input 文件）
- 运行测试与生成实际输出/Trace（`examples/` 的 output、trace 文件）
- 文档草稿（README、docs/01~05）

## 个人贡献


- 确定以题目和统一提交规范为验收依据，要求检查项目是否达标。
- 提出对批量排期冲突、保存失败、硬性要求和步数边界的专项复测要求。
- 针对多轮检测结果要求继续测试、完整回归和修复优化，推动实现迭代。



## 验证结果

- 测试：`python -m pytest tests/ -q --junitxml examples/test-results.xml` → **110 passed**（2026-10-28，Codex 运行并核对）。
- 示例（离线 Mock）：7 组输入、7 份输出、7 份 Trace 均由 AI 通过 CLI 实际运行生成。
- 示例（真实模型）：6 组输入、6 份输出、6 份 Trace（`examples/*_real.json`）经 DeepSeek `deepseek-v4-flash` 实际运行生成，覆盖正常、硬性边界、规则风险、信息缺失、保存失败、批量无冲突。
- 去重验证：`data/drafts.json` 二次运行后仍为 2 份草稿，`duplicate` 状态确认。

## 边界说明

- 真实模型路径已联调并验证（5 个场景），但真实模型的决策质量仍需候选人在更大样本上独立复核。
- 上述个人贡献依据候选人提供的信息和可核实的协作行为整理，候选人应在提交前复核其真实性。

## 2026-10-28 Claude Code 修复

用户按验收点逐项复测，指出若干边界漏洞，Claude Code 逐项修复并补测试与文档：

- 草稿去重改为稳定请求标识（素材ID/日期/时段），不再纳入 `review_status` / `pending_confirmations` 等模型措辞，避免真实模型换说法导致重复落盘。
- `save_draft` 前置拒绝「素材不存在 / 信息缺失 / 命中 block 规则」的草稿，阻断素材无法绕过审核落盘；守卫层独立重算审核结论，模型虚报的 approved/pending 被强制更正为 blocked/info_missing 并清空时段。
- 守卫对照工具实际落盘草稿，成功落盘素材的 `suggested_slot` 以真实草稿时段为准，纠正「保存 10:00 却报告 11:00」的虚报。

本轮未调用真实模型，也未替候选人填写个人贡献；测试结果只支持上述离线 Mock 与守卫流程，不代表真实模型决策效果。
