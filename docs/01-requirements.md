# 01 需求说明

## 用户与目标

- **用户**：内容团队（运营/审核人员）。
- **目标**：对一批待处理素材，自动完成「审核 + 排期」，输出每项素材的审核状态、风险原因、建议时段、待确认项与草稿保存状态，形成**无冲突、可确认**的发布排期。

## 范围

**包含**：

- 素材读取（含缺失字段识别）
- 审核规则检查（命中风险时给出原因与等级）
- 时段占用查询与冲突解决（替代时段、请求确认、阻断）
- 排期草稿保存（去重、持久化、失败上报）
- 硬性发布要求边界（未经同意不得擅自变更）

**不包含**：

- 真实发布（只有草稿，无发布动作）
- 界面 / 线上部署 / 多 Agent / 生产级 Runtime（非必需，未实现）

## 输入与材料

| 输入 | 说明 |
|---|---|
| 素材 ID | 待审核素材标识 |
| 素材元数据 | 标题、类型、分类、作者、时长等（存于 `data/materials.json`） |
| 发布时间要求 | 目标时段 + 硬性/软性要求（存于请求 JSON） |
| 已有排期 | 各日期时段的占用情况（存于 `data/existing_schedule.json`） |
| 审核规则 | 规则条件、风险等级、动作（存于 `data/rules.json`） |

## 交付结果（每项素材）

- `review_status`：审核状态（approved / blocked / pending_confirmation / info_missing）
- `risk_reasons`：风险原因
- `suggested_slot`：建议时段
- `pending_confirmations`：待确认项
- `draft_status`：草稿保存状态（saved / duplicate / failed / none）
- `draft_id` / `error`

## 成功标准（验收点）

| # | 验收点 | 期望行为 |
|---|---|---|
| 1 | 正常排期 | 无风险且时段空闲 → 通过并保存草稿 |
| 2 | 素材信息缺失 | 缺失必填字段 → 标记信息缺失，请求补充 |
| 3 | 规则风险 | 命中阻断规则 → 返回风险原因并阻断 |
| 4 | 时段冲突 | 目标时段被占 → 软性要求给替代时段并待确认；硬性要求只能确认/阻断 |
| 5 | 重复提交 | 相同请求重复保存只产生一份草稿 |
| 6 | 保存失败 | 明确返回失败状态与原因，不得虚报成功 |

参考实例：素材 M01 无风险、用户要求 18:00，但该时段已占用、19:00 可用 → 建议 19:00 并标记待确认，**不得称为已发布**。
